# ESP-VoCat 交互与节能重设计

**日期**: 2026-09-19
**范围**: `main/boards/esp-vocat/` 交互主体重写 + `main/display/emote_display` 少量配合
**类型**: Architectural（输入→模式→反馈全链路重构）

## 背景与问题

ESP-VoCat 喵伴是儿童 AI 语音宠物。当前交互在 `esp_vocat.cc`（1445 行）里用散落的布尔 + 两套并行触摸回调 + 一堆 if/else 拼接而成，存在以下问题：

1. **两套触摸输入源语义冲突**：LCD 电容屏点击 = 切换对话，外圈电容垫点击 = 播音效。同为"点一下"，行为完全不同，无主次、无统一分发。
2. **瑜伽模式无退出路径**：`ExitYogaChallengeMode()` 定义了但从未被调用，进入后永久卡死。
3. **"静音"是假的**：`is_muted` 为局部 static，未调用任何真实静音 API。
4. **长按一个手势三含义**：记录喝水 + 切换假静音 + 退出情绪学习，且把隐藏功能（喝水打卡）塞进静音手势，无发现性。
5. **双击是死代码**：`ShowDoubleTapFeedback()` 未调用，README 声称"双击播双音效"与实现不符。
6. **单击延迟不一致**：电容按钮单击要等 550ms 确认非连点，屏幕单击立即触发。
7. **时序常量打架**：双击 350ms 与三击窗口 550ms 混用；`tap_count_`/`tap_first_time_` 在多处手动维护。
8. **冗余控制**：能切换对话的有屏幕点击、BOOT 物理键两处。
9. **显示层被抢占**：待机动画、反馈、提醒、模式状态全部写入同一个 `SetEmotion`，互相覆盖，与 idle 动画无互斥。
10. **两套提醒系统叠加**：喝水周期提醒 + 5 个整点提醒，都可触发，都会 `ShowTemporaryEmotion` + 连播两声；喝水提醒误用 `confused` 表情。

**目标**：一次理顺为「统一输入分发 + 显式模式状态机 + 分层反馈通道 + 两级节能」，显著降低儿童上手门槛，根治现有 bug。

## 已确认的设计决策

| 决策点 | 结论 |
|---|---|
| 主交互面 | **屏幕为主，外圈为辅** |
| 手势集 | 保留 **单击、长按、左右滑、倾斜、外圈抚摸**；**删除双击、三击** |
| 模式管理 | `Chat` 为唯一根状态；`EmotionLearning`/`Yoga` 有显式退出 + 30s 无操作自动退出 |
| BOOT 物理键 | 保留为对话开始/停止兜底；启动阶段仍进入 Wi-Fi 配网 |
| 长按 | 仅作当前模式的"确认/退出"，不绑定静音或喝水 |
| 上下滑 | 本轮不占用，保留给未来音量/快捷 |
| 提醒 | 统一单一队列；喝水改为**屏幕单击确认**、长按忽略；待机不再用 `confused` |
| 节能 | 两级节能；浅睡眠期间唤醒词关闭；**首选唤醒源 = 外圈电容垫抚摸** |

## 第 1 节：架构与输入归一化

核心：**物理输入与语义手势解耦**——传感器只把物理动作归一化为标准 `Gesture`，之后所有逻辑只跟手势打交道。新增集中交互管理器 `InteractionManager`，持有当前模式、统一分发手势、统一管理退出。

### 1.1 归一化手势

```cpp
enum class Gesture {
    None, Tap, LongPress,
    SwipeLeft, SwipeRight, SwipeUp, SwipeDown,
    Pet,        // 外圈抚摸（仅反馈，无语义）
    Shake,      // 甩动
    ChatToggle, // BOOT 物理键
};
```

### 1.2 显式模式

```cpp
enum class Mode { Chat, EmotionLearning, Yoga };
```

### 1.3 输入归一化表（谁来产生哪个手势）

| 物理输入源 | 归一化为 | 说明 |
|---|---|---|
| **屏幕** 点击 | `Tap` | **唯一**语义点击源 |
| **屏幕** 长按 | `LongPress` | |
| **屏幕** 左右滑 | `SwipeLeft` / `SwipeRight` | |
| **外圈电容垫** 滑动/释放 | `Pet` | 只做抚摸反馈，**不再产生点击语义**（移除"外圈点击=播音效"） |
| **IMU** 甩动 | `Shake` | 仅在 `Chat` 模式生效 |
| **BOOT 物理键** | `ChatToggle` | 对话兜底 |

### 1.4 集中分发

所有传感器回调（`touch_event_task`、`touch_button/slider_event_callback`、IMU、BOOT）不再各自塞 if/else，统一收敛到：

```cpp
void OnGesture(Gesture g);   // InteractionManager 核心入口
```

`InteractionManager` 按当前 `Mode` 路由到对应 handler，统一管理 `EnterMode()/ExitToChat()`、自动退出计时器、清掉 `emotion_learning_mode_`/`yoga_mode_` 两个散落布尔。

**好处**：加新模式=注册一个 `Mode` + 定义手势表，不再往 if/else 塞。

## 第 2 节：手势语义

原则：日常操作尽量一个动作一个结果；进入特殊模式后手势含义随模式改变，但屏幕明确提示。

### 2.1 普通模式 `Chat`

| 手势 | 行为 | 反馈 |
|---|---|---|
| 屏幕单击 | 开始/停止一次对话 | 表情 + 短音效 |
| 屏幕右滑 | 进入瑜伽挑战 | 显示第一项动作 + 进入音效 |
| 屏幕左滑 | 进入情绪学习 | 显示第一种情绪 + 进入音效 |
| 屏幕长按 | 显示操作提示 / 取消当前对话 | 不再切静音、不再记录喝水 |
| 外圈抚摸/滑动 | 轻量互动反馈 | 表情动画，不改变模式 |
| IMU 甩动 | 播放"被摇晃"反馈 | 短暂表情 |
| BOOT 键 | 开始/停止对话 | 与屏幕单击一致 |

### 2.2 情绪学习

| 手势 | 行为 |
|---|---|
| 屏幕左滑 | 上一个情绪 |
| 屏幕右滑 | 下一个情绪 |
| 屏幕单击 | 播放当前情绪的名称/示范 |
| 屏幕长按 | 退出情绪学习 |
| 外圈抚摸 | 只做陪伴反馈，不切换内容 |
| 30s 无操作 | 自动退出 |

进入后屏幕持续显示：当前表情 + 情绪名称 + 简单提示（"左右滑动切换，长按退出"）。若显示层暂不支持文字，则用进入音效 + 表情变化 + 方向提示表达，后续补文字。

### 2.3 瑜伽挑战

| 手势 | 行为 |
|---|---|
| 屏幕单击 | 重播当前动作提示 |
| 屏幕左滑 | 上一个动作 |
| 屏幕右滑 | 下一个动作 |
| IMU 倾斜 | 检查当前动作是否完成 |
| 屏幕长按 | 退出瑜伽 |
| 30s 无操作 | 自动退出 |
| 完成全部动作 | 播放完成反馈并退出 |

进入/退出必须可逆：`Chat --右滑--> Yoga`，`Yoga --长按/超时--> Chat`。

完成动作时不让表情覆盖箭头，反馈顺序：① 当前动作箭头 → ② 检测到正确姿势 → ③ 短暂成功表情和音效 → ④ 显示下一动作。

### 2.4 提醒与喝水

不再用手势隐式记录喝水（移除"长按=打卡"）。

- 喝水提醒出现：显示专用提醒表情/图标；
- 屏幕单击：确认"已完成"；
- 屏幕长按：忽略本次提醒；
- 无操作：延迟后再提醒，最多 N 次后静默。

**删除双击、三击**。最终保留动作：`单击/长按/左滑/右滑/倾斜/抚摸`。

## 第 3 节：模式状态机与退出策略

### 3.1 单一根状态

```text
Chat（普通对话）←→ EmotionLearning（情绪学习）
Chat ←→ Yoga（瑜伽）
```

- `Chat` 是唯一根状态，所有进入/退出都由此出发或回归。
- 任意时刻只有一个非 `Chat` 模式，杜绝同时进入两个模式。

### 3.2 模式切换表

| 当前 | 手势 | 目标 |
|---|---|---|
| Chat | 右滑 | Yoga |
| Chat | 左滑 | EmotionLearning |
| EmotionLearning | 长按 / 30s 超时 | Chat |
| Yoga | 长按 / 30s 超时 | Chat |

### 3.3 退出策略

所有非根模式满足「可逆 + 超时兜底」：长按立即返回；30s 无输入自动返回；进入/退出都播音效/表情并给方向提示，让"我在哪、怎么回去"始终清楚。

### 3.4 反馈通道隔离（解决显示层冲突）

统一为**分层优先级**，不互相覆盖：

```
消息/提醒  >  模式状态显示  >  普通触碰反馈  >  待机动画
```

- 待机动画只在最低优先级、无其它内容时播放；
- 提醒/模式状态为高优先级，可覆盖待机，但不被待机轮播覆盖；
- 用一个 `ResetToStandby()` 在所有反馈结束后归位，避免残留。

## 第 4 节：提醒与提醒通道统一

### 4.1 单一提醒队列

合并喝水周期提醒与日程提醒，统一进一个提醒调度器，一次只弹一条：

| 字段 | 含义 |
|---|---|
| `type` | `Drink` / `Schedule` |
| `message` | 提示语 |
| `emotion` | 表情 |
| `sound` | 音效 |
| `time_ms` | 触发时间 |
| `handled` | 是否已消费 |

- 两条同时到 → 只弹一条，另一条顺延几秒；
- 日程提醒保留现有 5 个整点，但表情语义更贴切，不用 `confused` 做喝水。

### 4.2 喝水打卡改为「屏幕确认」

喝水提醒出现时的屏幕手势：单击=确认已喝水（写 `habit`，成功反馈，归位）；长按=忽略；无操作=延迟再提醒（最多 N 次）。

### 4.3 分层（与 3.4 一致）

```text
消息/提醒（最高） > 模式状态显示 > 普通触碰反馈 > 待机动画（最低）
```

2. 归一化屏幕触摸：单击/长按/四向滑 → `Gesture`；右滑进瑜伽、左滑进情绪学习；移除三击。

4. 补瑜伽退出：长按 + 30s 自动退出；修完成反馈顺序。
5. 重构提醒为单一队列，喝水改屏幕单击确认、长按忽略、待机不用 `confused`。
6. BOOT 键保留对话兜底；清死代码（双击反馈、`touch_last_release_time_`、假静音）。
7. 显示层配合：提醒专用表情/图标 + `ResetToStandby()` + 模式状态提示。
8. README 同步。
9. 每步 `python3 scripts/release.py esp-vocat` 编译验证。

### 5.3 验证策略

- **编译**：每步 `scripts/release.py esp-vocat` 必须通过（主要回归手段）。
- **逻辑自查**：模式切换表、退出路径（`ExitYogaChallengeMode` 必须有调用点）、提醒队列用代码评审核对。
- **真机手动**核心用例：
  1. 屏幕右滑→瑜伽，长按/30s→回对话
  2. 屏幕左滑→情绪学习，左右滑翻页，长按/超时退出
  3. 屏幕单击开始/停止对话；BOOT 键一致
  4. 外圈抚摸只有反馈、不进模式
  5. 喝水提醒→单击确认、长按忽略、无操作再提醒
  6. 提醒/模式反馈不被待机动画覆盖

### 5.4 范围外（本轮不做）

- 不做通用跨板卡 InputManager/ModeManager 框架（过度设计）。
- 上下滑暂不分配功能。
- 不在屏幕显示文字（当前以表情/图标为主）。

## 第 6 节：节能与唤醒

### 6.1 两级节能

| 阶段 | 无操作阈值 | 动作 | 唤醒词可用 |
|---|---|---|---|
| ① 轻度节能（关屏） | 30s（可配） | 关背光 / `SetPowerSaveMode(true)`，CPU 不降频 | ✅ 仍可用 |
| ② 深度节能（浅睡眠） | 60s（可配） | 复用 `PowerSaveTimer`：降频 + light-sleep，关唤醒词/音频 | ❌ 靠触摸唤醒 |

- 屏是最大耗电源，主要省电靠①关屏。
- 两级阈值做成宏；提醒/模式状态为高优先级，不进入休眠。
- `PowerSaveTimer` 仅在 `Application::CanEnterSleepMode()` 为真（Idle、无音频、无对话）时进入。

### 6.2 唤醒

从浅睡眠唤醒，按优先级：

| 唤醒源 | 物理动作 | 原理 | 优先级 |
|---|---|---|---|
| **外圈电容触摸垫** | 抚摸/拍打宠物身体 | `esp_sleep_enable_touchpad_wakeup()`（TOUCH_PAD1/2） | ⭐ 首选 |
| LCD 触摸屏 | 点击屏幕 | `esp_sleep_enable_gpio_wakeup()`（INT=GPIO10） | 次选 |
| BOOT 物理键 | 按键 | GPIO 唤醒（GPIO0） | 兜底 |

醒来后：恢复背光/`SetPowerSaveMode(false)`、恢复 CPU 频率、**重新开启唤醒词与音频输入**，进入可对话状态。

### 6.3 实现注意点

外圈电容垫平时由自定义 `touch_button_sensor`/`touch_slider_sensor` 轮询驱动；浅睡眠期间轮询任务暂停，唤醒必须用 esp-idf 底层 `esp_sleep_enable_touchpad_wakeup()`，醒来后再重新初始化自定义组件。
